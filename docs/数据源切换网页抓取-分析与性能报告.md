# 数据源切换为「网页抓取」问题分析报告与性能测试结果

> 日期：2026-08-06
> 范围：PHILIA 龙头情绪复盘（「重新分析」功能）数据源
> 目标：1) 完全断开本地 KPL API，严格按网页抓取获取数据；2) 提升获取与处理流程的响应速度。

---

## 一、问题分析

### 1.1 现象
点击「重新分析」按钮后，用户界面（UI）数据源仍显示来自 KPL（开盘啦）等本地 API 接口，与用户要求的「从网页抓取数据」配置不符。

### 1.2 根因分析

| 类别 | 根因 |
|------|------|
| 数据源耦合 | 后端 `philia-ai.cjs` 的 `assembleContext()` 通过 `KPL_BASE` 代理地址调用本地 KPL 接口（`kplFetch`），白皮书字段全部来自本地代理通道。 |
| 前端标签 | 前端 `PhiliaVisualization.tsx` 硬编码了「KPL 开盘啦」数据源标签，未随数据源切换更新。 |
| 依赖残留 | 数据库 `stock-db.cjs` 中仍缓存有 KPL 相关历史数据，存在复用旧数据风险。 |

**结论**：数据获取、字段组装、前端展示三层均仍指向 KPL，属于「数据源未真正切换」而非单纯 UI 显示问题。

---

## 二、技术解决方案

### 2.1 数据获取层：本地 KPL → 东方财富网页公开接口
在 [server/philia-ai.cjs](file:///c:/Users/A/Desktop/峰策/驾驶舱改%20-%20副本/server/philia-ai.cjs) 中移除全部 KPL 客户端代码（`KPL_BASE`、`KPL_API_KEY`、`kplFetch`），改为直连东方财富公开网页接口：

| 数据 | 接口 |
|------|------|
| 涨停池 | `push2ex.eastmoney.com/getTopicZTPool` |
| 炸板池 | `push2ex.eastmoney.com/getTopicZBPool` |
| 跌停池 | `push2ex.eastmoney.com/getTopicDTPool` |
| 全市场涨跌家数 | `push2delay.eastmoney.com/api/qt/ulist.np/get`（聚合上证+深证 `f104/f105/f106`） |

**稳定性保障**：
- `dns.setDefaultResultOrder("ipv4first")` 强制 IPv4，规避本机 IPv6 连接不稳定。
- `fetch` → `curl.exe` 双重回退，兼容 TLS 指纹敏感上游。
- 4 路数据源用 `Promise.allSettled` 并行拉取，任一失败不影响整体。

### 2.2 字段一致性
新数据源字段结构与原 KPL 白皮书口径保持一致（`mood` / `riseFall` / `themeHot` / `youzi` / `liveLadder` 等），确保 LLM prompt 结构不变、解析结果稳定。

### 2.3 前端展示层
- [PhiliaVisualization.tsx](file:///c:/Users/A/Desktop/峰策/驾驶舱改%20-%20副本/src/components/dash/PhiliaVisualization.tsx)：数据源标签由「KPL 开盘啦」改为「东方财富网页数据」。
- [MarketReviewSection.tsx](file:///c:/Users/A/Desktop/峰策/驾驶舱改%20-%20副本/src/components/dash/MarketReviewSection.tsx)：数据源区域通过 `sources` 数组动态渲染，已无硬编码 KPL 字样，展示「东方财富·涨停池」等 4 路网页来源及获取时间。

### 2.4 缓存与降频
- 数据白皮书缓存 `CONTEXT_CACHE_TTL = 5min`，避免高频重复抓取。
- 分析结果降频缓存 `ANALYSIS_CACHE_TTL = 30min`，「重新分析」传 `force=true` 绕过缓存强制刷新。

## 三、实施后的性能测试结果

### 3.1 测试方法
独立脚本 [server/perf-test-web.cjs](file:///c:/Users/A/Desktop/峰策/驾驶舱改%20-%20副本/server/perf-test-web.cjs) 对 4 路网页数据源连续测试 8 次，对比**并行模型**（生产采用）与**串行模型**（旧式顺序请求）。

### 3.2 测试结果

| 指标 | 并行模型（生产） | 串行模型（对比） |
|------|:---:|:---:|
| 成功率 | **100%** | 100% |
| 平均耗时 | **99ms** | 225ms |
| P50 | **66ms** | 228ms |
| Max | **268ms** | 231ms |
| 各次耗时 | 268/144/63/64/71/65/54/66ms | 219/231/228/214/223/230/225/231ms |

**并行相对串行提速 2.3 倍**；数据抓取阶段平均 **99ms** 即可完成，叠加 5min 白皮书缓存后，常规「重新分析」的数据获取几乎无感。

### 3.3 数据有效性
最近一次测试返回 **涨停家数 103**，涨停/炸板/跌停池与全市场涨跌家数均正常返回，字段解析正确。

### 3.4 端到端链路确认
- `assembleContext()` 已完全走网页数据源，`SRC_NAMES = ["东方财富·涨停池","东方财富·炸板池","东方财富·跌停池","东方财富·全市场涨跌家数"]`。
- `result.sources` 携带上述网页来源标签透传前端，UI 数据源面板动态渲染。
- 已清理 `stock-db.cjs` 中 KPL 缓存数据，杜绝旧数据复用。

## 四、结论
1. **数据源已完全断开本地 KPL**：抓取、组装、展示三层均已切换为东方财富网页公开接口，无 KPL 运行时代码残留（仅注释保留说明）。
2. **响应显著提升**：数据抓取平均由串行 225ms 降至并行 99ms（2.3x），成功率 100%，配合缓存机制进一步降低用户等待时间。
