## 二、接口彻查：问题发现

### 2.1 性能问题（高）

| ID | 位置 | 问题 |
|----|------|------|
| P1 | philia-ai.cjs `assembleContext` | 白皮书组装存在 4 级串行 await 链（昨日板块→昨日涨停今表现→龙头池→K线），最坏 6~19s |
| P2 | philia-ai.cjs `fetchIndexYesterday` | 三大指数日K **串行** 抓取（各自最多 3 次重试×8s） |
| P3 | philia-ai.cjs `calcYestLimitUpPerformance` | 昨涨停股行情最多 6 批 **串行** 请求 |
| P4 | philia-ai.cjs `loadSkills`/`buildSkillIndex`/`loadLuotouObjectiveData` | 每次分析**全量重读 20+ 技能文件**，三处各自独立读盘，无缓存 |
| P5 | index.cjs `thsMinuteFetch` | A股个股分时中 minute 与 quote（昨收）**串行**请求，分时图加载多一次往返 |
| P6 | index.cjs `/api/minutes` | 单路慢指数（usN225/usKS11 经不稳定 push2his，重试链 3×8s）拖死整个批量；缓存 TTL(5s) < 轮询周期(15s)，每轮都冷抓上游 |
| P7 | philia-ai.cjs `callLLM` | LLM 调用无重试，429/5xx/网络闪断直接 502 |
| P8 | philia-ai.cjs `buildStockInput` | 个股恰在白皮书重点池中时仍重复发 3 个 K 线请求 |

### 2.2 正确性/存储问题（中）

| ID | 位置 | 问题 |
|----|------|------|
| C1 | philia-ai.cjs / stock-db.cjs | `ANALYSIS_CACHE_TTL`(30min) 定义了但从未使用——缓存命中实为"当日永久"；`ai_analysis` 表无过期清理，长期无限增长 |

### 2.3 安全/参数校验问题（中）

| ID | 位置 | 问题 |
|----|------|------|
| S1 | `/api/stock-detail`、`/api/stock-boards` | 接受任意 code 字符串，非法值会 `upsertStock` 落库污染 stocks 表 |
| S2 | `/api/stock-main-forces` | 非法 code 抛错走 502（客户端错误语义错位），且每次请求重复触发上游 |
| S3 | `/api/minutes`、`/api/quotes` | codes 列表无数量上限与格式白名单，单请求可放大为数百次上游调用 |
| S4 | 静态文件服务 | 畸形 `%` 编码 URL 抛 URIError → 500（应为 400） |
| S5 | `validPeriod` | `9999-99-99` 等格式合法但日期非法值穿透到上游 |
| S6 | `makeLimiter` | 限流计数 Map 无容量上限，伪造 IP 轮换可撑爆内存 |
| S7 | `/api/monitor` | lastErr 含内部错误文本、dbPath 含绝对路径，未受跨源保护 |
| S8 | `/api/philia/leader-pool?force=1` | 重成本操作（清缓存全量重抓）共用宽松通用限流(240/min) |
| S9 | 分发层 | `isLlmbilling` 引用不存在的路由 `/api/philia/analyze`（死引用） |

### 2.4 设计/文档问题（低）

- 已清空接口（boards/board-stocks/rank/moneyflow/news）仍注册并按用户输入拼缓存 key；
- 约 12 个接口（quotes/minutes/stock-flows/treasuries 等）缺输入/输出/缓存策略注释；
- `launch-hexin`/`topmost` 失败返回 200+嵌套 `{ok:false}`，与抛 4xx 的接口风格不一（前端已适配，未改）。

## 三、解决方案与实施步骤

### 3.1 性能优化（已实施）

| # | 改动 | 文件 | 实施要点 |
|---|------|------|---------|
| 1 | **白皮书组装并行化** | philia-ai.cjs | 将 4 级串行链压为 2 级：`Promise.allSettled([fetchBoardYesterday, calcYestLimitUpPerformance, leaderPoolGetter])`；yestPool/yesterdayMatch 同步前置；K线仍依赖 leaderPool 串行其后 |
| 2 | **指数昨日因子并行** | philia-ai.cjs | `fetchIndexYesterday` 三指数改 `Promise.allSettled` 并行 |
| 3 | **昨涨停今表现并发** | philia-ai.cjs | `calcYestLimitUpPerformance` 分批请求改 3 路并发 worker |
| 4 | **技能文件磁盘缓存** | philia-ai.cjs | 新增 `readFileCached`（mtime 校验失效）+ `cachedSkills`/`cachedSkillGroups`/`cachedSkillIndex`（技能库文件摘要做失效 key）；`loadSkills`/`buildSkillIndex`/`loadLuotouObjectiveData`/`loadQushiObjectiveData` 全部走缓存，消除重复读盘 |
| 5 | **个股分时并行** | index.cjs | `thsMinuteFetch` 中 minute 与 quote（昨收）并行拉取 |
| 6 | **批量分时降级** | index.cjs | `/api/minutes` 每路加 `withTimeout(8s)`；`getMinute` TTL 5s→20s（>15s 轮询周期，轮询间隔内命中）；usN225/usKS11 差异化 TTL 60s + emGetHis 收紧 5s 总超时快速降级 |
| 7 | **LLM 调用重试** | philia-ai.cjs | `callLLM` 对网络错误/429/5xx 重试 1 次（3s 退避），4xx 业务错误不重试 |
| 8 | **K线因子复用** | philia-ai.cjs | `buildStockInput` 优先复用 `contextCache.data.stockKFactors` 中已抓因子 |

### 3.2 正确性/存储（已实施）

| # | 改动 | 文件 |
|---|------|------|
| 9 | 启用 `ANALYSIS_CACHE_TTL`（30min）命中校验 | philia-ai.cjs（analyze/analyzeMarket 两处） |
| 10 | `cleanupAiAnalysis(ttlMs)` 定期清理过期缓存行（每小时至多一次） | stock-db.cjs + philia-ai.cjs |

### 3.3 安全/参数校验（已实施）

| # | 改动 | 文件 |
|---|------|------|
| 11 | `handleStockDetail` / `/api/stock-boards` code 校验（`/^(sh|sz|bj)\d{6}$/`），非法抛 400 | index.cjs |
| 12 | `handleStockMainForces` 非法 code 返回 null（按空数据处理） | index.cjs |
| 13 | 新增 `sanitizeCodes`（格式白名单 + 100 上限），应用于 `/api/quotes`、`/api/minutes` | index.cjs |
| 14 | 畸形 `%` 编码 URL 回 400 | index.cjs |
| 15 | `validPeriod` 校验真实日期（非法回退默认报告期） | index.cjs |
| 16 | `makeLimiter` 加容量上限（10000，最旧淘汰） | index.cjs |
| 17 | `/api/monitor` 加入 PROTECTED_ROUTES（跨源保护） | index.cjs |
| 18 | `leader-pool?force=1` 复用私有端点限流(20/min) | index.cjs |
| 19 | 清理 `/api/philia/analyze` 死引用 | index.cjs |

### 4.3 结构性收益（无法直接采样的改动）

| 改动 | 预期收益 |
|------|---------|
| 白皮书组装并行化 | 首次分析白皮书组装时间从最坏 ~6-19s 压到最大单项（K线 ~6s），**并行后与 LLM 分析时间重叠** |

## 五、测试结果

### 5.1 功能回归（全部通过）

| 用例 | 结果 |
|------|------|
| `GET /api/stock-detail?code=foo` | ✅ 400（新校验生效） |
| `GET /api/stock-detail?code=sh600519` | ✅ 200，数据完整 |
| `GET /api/stock-boards?code=bad` | ✅ 400 |
| `GET /api/minutes?codes=sh000001,sz399001,invalid,999…` | ✅ 200，非法代码被过滤 |
| `GET /api/quotes?codes=sh000001,sz399006,badcode,usVIX` | ✅ 200，多源正常 |
| `GET /api/monitor` | ✅ 200（加入 PROTECTED_ROUTES 后同源正常） |
| `POST /api/philia/market-analyze`（force，真实 LLM） | ✅ 200，38s（含 LLM），5 模块齐全，14 路数据源，`fromCache=false` |
| 分析结果缓存命中（30min TTL 内） | ✅ 命中返回，不重复计费 |
| `ai_analysis` 过期清理 | ✅ 启动即清理 32 条过期记录 |
| 技能文件缓存（改版自动失效） | ✅ mtime 摘要校验，文件未变直接复用 |

### 5.2 已知限制

- `usN225`/`usKS11`（新浪全球日线）受上游网络波动影响，已通过 5s 超时降级（空点）+ 60s 长 TTL 缓解，非后端可控；
- `board-flow`/`stock-flows` p95 约 2.5~3s，为东财上游慢响应 + 已有缓存，受外部制约。

## 六、后续改进建议（未实施）

| 优先级 | 建议 | 说明 |
|--------|------|------|
| 高 | `isSameOrigin` 对无 Origin/Referer 请求放行（curl 可绕过 PROTECTED_ROUTES 403） | 本地工具可接受；若公网部署需加访问令牌或 IP 白名单 |
| 高 | 限流 `clientIp` 信任 `CF-Connecting-IP`/`X-Forwarded-For`，伪造头可绕过 | 部署在 CF Tunnel 后为真；非 CF 环境建议环境变量开关 |
| 中 | `/api/ths/account` 密码明文落盘 → 仿 `philia-keystore.cjs` 加密存储 | 敏感凭据保护 |
| 中 | `/api/minutes` 指数面板增量刷新：前端传"上次数据时间"，后端仅补增量 | 进一步降低上游流量 |
| 中 | `contextToText` 大字符串同步拼接可分段（token 裁剪前） | 极端数据量下 CPU 优化 |
| 低 | 已清空接口（boards/rank/moneyflow/news）移除 `cached` 包裹或整体下线 | 减少缓存槽占用与扫描面 |
| 低 | 为 quotes/minutes/stock-flows/treasuries 等补齐 JSDoc | 文档完整性 |
| 低 | 统一 `launch-hexin`/`topmost` 错误表达为抛 4xx | 需前端同步适配 |
